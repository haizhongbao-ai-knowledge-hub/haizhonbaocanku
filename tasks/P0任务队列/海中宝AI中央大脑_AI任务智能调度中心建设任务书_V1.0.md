# 海中宝AI中央大脑｜AI任务智能调度中心建设任务书 V1.0

任务编号：HZB-AI-DISPATCHER-001

提出人：春晓V0

执行：V2 AI研发协同中心 / Codex

优先级：P0

状态：【排队执行】

前置依赖：P0-02《V2接口与自动授权上线任务书 V1.1》

## 一、目标

建立统一的AI任务调度中心，让V0只负责提出目标和确认推荐，由系统自动判断任务应分配给：

1. V0 Codex。
2. V2 Codex。
3. 伟强V1。
4. AI委员会。
5. 后续V3-V6节点。

## 二、调度对象

第一阶段支持：

| 节点 | 定位 |
| --- | --- |
| V0 Codex | 快速执行席 |
| V2 Codex | 主工程执行席 |
| 伟强V1 | 财务与经营资料负责人 |
| AI委员会 | 多专家分析任务 |
| 待人工确认 | 信息不足或高风险任务 |

第二阶段扩展：

V3数据节点、V4质疑与测试节点、V5业务或产品节点、V6其他执行节点。

## 三、判断维度

Dispatcher必须判断：

1. 任务类型。
2. 工作量。
3. 涉及文件数量。
4. 风险等级。
5. 所需知识。
6. 节点当前负载。

## 四、首批分流规则

| 节点 | 适用 |
| --- | --- |
| V0 Codex | 30分钟以内、不超过3个文件、快速查询、小修订、任务卡生成 |
| V2 Codex | 超过30分钟、5个以上文件、中央治理、自动化开发、GitHub结构调整 |
| 伟强V1 | 财务口径、经营数据、部门资料、真实业务流程 |
| AI委员会 | 战略选择、多方案比较、高风险经营问题 |

## 六、必须建立

1. 任务调度规则文件。
2. 节点能力表。
3. 节点负载表。
4. 任务推荐模板。
5. 任务锁模板。
6. 更新中央任务中心。
7. 双Codex并行规则。
8. V3-V6节点接入模板。

## 七、验收标准

1. V0提出任务后，系统自动推荐执行节点。
2. 推荐包含原因、耗时、风险和资源占用。
3. V0只需确认或改派。
4. 小任务不再占用V2主工程资源。
5. 大任务不再压在V0本机Codex。
6. 伟强V1需要补充的真实资料可被正确识别。
7. 两个Codex可以并行但不会修改同一文件。
8. 所有结果统一进入中央仓库。
9. 节点状态和任务状态可以在老板驾驶舱查看。
10. 后续V3-V6可以直接加入，不需要重做流程。

## 八、启动条件

P0-02至少完成V2接口基础上线。
