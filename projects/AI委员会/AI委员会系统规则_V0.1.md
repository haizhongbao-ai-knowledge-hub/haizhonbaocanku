# 海中宝AI委员会会议系统 V0.1

项目编号：HZB-AI-COMMITTEE-001

状态：【V0.1 建设中，待老板确认后正式启用】

负责人：

- 春晓V0（Owner）
- 伟强V1（AI项目推进负责人）

## 一、项目背景

海中宝正在建设：

```text
海中宝AI中央大脑
```

目标不是简单使用AI聊天，而是建立企业级AI决策系统。

未来公司任何人员提出经营问题，都可以通过AI委员会：

- 调用不同岗位AI专家。
- 从企业利益角度分析。
- 形成高质量决策方案。
- 进入执行与复盘闭环。

## 二、核心理念

AI身份独立于设备。

原则：

```text
AI角色 ≠ 电脑
AI角色 ≠ GPT账号
AI角色 ≠ 单个聊天窗口
```

结构：

```text
AI身份
↓
权限
↓
知识库
↓
GPT/Codex运行环境
↓
电脑/服务器
```

## 三、第一阶段实现方式

采用：

```text
GPT + Codex + GitHub中央文件
```

暂不开发APP。

原因：

- 当前重点是验证AI组织协同流程。
- 先用文件系统跑通会议闭环。
- 确认价值后再开发浏览器插件、AI工作台或企业AI操作系统。

## 四、系统结构

```text
海中宝AI中央大脑
        ↓
AI委员会系统
        ↓
项目会议空间
        ↓
战略AI / 数据AI / 财务AI / 质疑AI / 业务AI / 产品AI / 设计AI / 供应链AI / HR AI
        ↓
会议结果
        ↓
决策文件
        ↓
知识库沉淀
```

## 五、问题入口系统

提出问题的人不限：

- 老板
- CEO
- 部门负责人
- 普通员工
- GPT账号用户

但任何问题必须先经过AI问题秘书整理。

## 六、AI问题整理流程

AI问题秘书不能马上回答。

必须先确认：

1. 真实问题是什么？
2. 缺少什么数据？
3. 影响什么业务？
4. 需要哪些AI专家？

输出：

```text
AI问题分析单
```

## 七、AI委员会会议流程

### Step 1：问题进入

生成会议编号。

示例：

```text
HZB-PRODUCT-001
```

### Step 2：AI秘书拆解

生成：

- 问题
- 背景
- 目标
- 限制条件
- 需要回答
- 参与AI

### Step 3：AI专家独立分析

默认专家顺序：

1. 战略AI
2. 数据AI
3. 财务AI
4. 业务AI
5. 产品AI / 设计AI
6. 供应链AI
7. HR AI
8. 质疑AI

每个AI必须独立输出观点，不能只附和前一个AI。

### Step 4：AI虚拟CEO综合

整理：

```text
AI委员会综合建议
```

### Step 5：春晓V0决策

春晓V0负责批准、否决或要求补充。

### Step 6：伟强V1推进

伟强V1负责协调、跟踪、文件、Codex任务推进。

### Step 7：Codex执行

Codex只依据正式确认文件执行。

## 八、决策权限

| 身份 | 权限 | 责任 |
| --- | --- | --- |
| 春晓V0 | 最高决策 | 批准 / 否决 / 最终授权 |
| 伟强V1 | 项目推进 | 协调、跟踪、文件、Codex任务 |
| GPT | 战略与综合 | 分析、方案、风险、会议综合 |
| Codex | 工程执行 | 文件、系统、自动化、同步 |
| AI专家 | 专业建议 | 独立分析，不替代老板决策 |

## 十、V0.1 MVP功能

Codex优先实现：

1. 会议创建模板。
2. AI角色模板。
3. 会议结果自动归档规则。
4. 状态同步规则。

## 十一、禁止事项

- 禁止创建第二套中央大脑。
- 禁止把会议聊天当作最终依据。
- 禁止无限聊天不输出结果。
- 禁止AI专家直接替代老板决策。
- 禁止绕过权限读取敏感资料。
- 禁止未形成决策文件就要求Codex执行。

## 十二、未来扩展

第二阶段：浏览器插件。

第三阶段：AI工作台。

第四阶段：企业AI操作系统。

## 十三、验收标准

V0.1完成后，必须实现：

```text
一个员工提出问题
↓
AI整理问题
↓
调用多个AI专家
↓
输出综合方案
↓
V0/V1收到结果
↓
决策记录进入中央大脑
```

## 十四、永久原则

老板知道。

GPT理解。

Codex同步。

文件记录。

否则不能执行。
