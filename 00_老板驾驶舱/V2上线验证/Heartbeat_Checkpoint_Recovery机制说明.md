# Heartbeat、Checkpoint、Recovery机制说明

状态：【机制已建立，持续运行待V2上线验证】

版本：V1.0

## 一、Heartbeat

Heartbeat用于让V0 GPT、V0 Codex和老板看到V2当前状态。

V2必须持续同步：

1. 当前任务。
2. 下一任务。
3. 当前负载。
4. 阻碍。
5. Git状态。
6. 待V0审批。
7. 待V1资料。

正式文件：

`00_老板驾驶舱/AI节点总览/V2_HEARTBEAT.md`

## 二、Checkpoint

Checkpoint用于防止长任务中断后丢失进度。

触发条件：

1. 开始执行任务。
2. 完成一组文件创建。
3. 修改状态中心前。
4. Git add前。
5. commit前。
6. push前。
7. 发现卡住或权限申请中断时。

记录内容：

1. 当前任务。
2. 已完成文件。
3. 未完成文件。
4. Git状态。
5. 当前阻碍。
6. 下一步恢复动作。

## 三、Recovery

Recovery用于任务卡住后的自动恢复。

恢复规则：

1. 先检查Git状态。
2. 如果本地commit已完成，检查是否领先origin。
3. 如果领先origin，继续push。
4. 如果push权限卡住，重新申请权限。
5. 如果存在未跟踪文件，继续归档、提交、备份。
6. 如果任务耗时预计在几分钟到十几分钟，卡住后自动重新检查并继续。
7. 如果任务预计超过30分钟，可进入二次启动，但必须保留Checkpoint。

## 四、禁止事项

1. 禁止卡住后重新开始一套新目录。
2. 禁止覆盖未确认文件。
3. 禁止跳过Git状态检查。
4. 禁止虚报云端同步成功。

## 五、当前结论

机制文件已建立。

V2持续Heartbeat和真实Recovery演练待V2上线后执行。
