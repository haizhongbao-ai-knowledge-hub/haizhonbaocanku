# 海中宝AI中央大脑智能体一键接入入口 V2.0

状态：【智能体一键接入协议 V2.0】

更新日期：2026-07-28

项目编号：HZB-AI-CENTRAL-BRAIN

## 文件定位

本文件是海中宝所有AI智能体的唯一入口文件。

本文件定位为“稳定启动器”。

后续中央大脑继续升级时，优先更新中央导航地图、项目状态总览、身份权限验证表、岗位知识库和项目文件；除非接入流程发生重大变化，本入口文件不频繁更换。

老板日常只需要提供本入口文件。

后续资料加载、岗位知识读取、权限升级和项目同步，优先通过GitHub中央仓库或本地中央仓库完成，不要求老板反复上传很多文件。

适用于：

- 新GPT账号
- 新ChatGPT窗口
- 新Codex账号
- 新电脑
- 新AI员工
- 后续第三方AI模型

## 一、启动规则

当AI读取本文件后，不得直接执行业务。

```text

```


## 三、身份验证

初期采用简单验证。

填写：

```text

```

验证原则：

不是验证个人隐私，而是确认这个AI应该服务谁。

真实密码、口令、验证码不得写入GitHub仓库。

## 四、中央大脑连接

AI按层读取：

第一层：

```text
接入包_给GPT和Codex/海中宝AI中央大脑智能体一键接入入口_V2.0.md
```

第二层：

```text
接入包_给GPT和Codex/中央大脑导航地图.md
```

第三层：

```text
海中宝AI项目状态总览.md
```

第四层：

```text
00_海中宝AI治理总纲/07_运行制度/AI身份权限验证表.md
```

第五层：

```text
对应岗位知识库
```

重要说明：

入口文件只负责启动接入流程。AI不能只依赖本文件判断最新状态，必须继续读取最新中央导航地图、项目状态总览和权限文件。

资料加载原则：

```text
老板只给一个入口文件
↓
AI根据入口找到中央仓库
↓
AI读取中央导航地图
↓
AI按身份和岗位申请权限
↓
AI从中央仓库读取对应资料
↓
进入岗位工作模式
```

如果AI不能直接访问GitHub或本地仓库，才请求老板提供备用文件。

## 五、岗位自动匹配

中央根据以下信息匹配AI身份：

- 岗位
- 职责
- 负责人
- 申请方向
- 权限等级

重要原则：

```text
授权智能体身份，不授权GPT账号本身。
```

同一个GPT账号可以在不同时间进入不同AI岗位。

权限由当前智能体身份、岗位、负责人和老板授权共同决定。

示例：

用户申请“招聘AI”。

中央生成：

```text
AI编号：HZB-HR-AI-001
岗位：HR招聘智能体
职责：
- 招聘流程优化
- 人才画像设计
- 招聘话术
- 面试体系

读取权限：
允许：
- 企业介绍
- 组织架构
- 岗位资料
- 薪酬制度

禁止：
- 财务数据
- 经营利润
- 员工个人隐私

权限：P2
```

## 十一、入口文件稳定规则

老板可能把本文件长期保存在手机或优盘。

未来普通升级不要求老板频繁更换本文件。

普通升级包括：

- 新增AI岗位
- 新增岗位知识库
- 新增业务项目
- 更新权限矩阵
- 更新项目状态
- 更新老板驾驶舱

这些升级应写入中央仓库内的导航、状态、权限和知识库文件。

只有当GitHub仓库地址、项目编号、入口命名或接入流程发生根本变化时，才需要替换本入口文件。

## 十二、一个文件接入规则

海中宝中央大脑的目标不是让老板不断传文件。

标准方式：

```text
第一次：老板只提供本入口文件
第二步：AI读取中央仓库导航
第三步：AI提交身份和岗位申请
第四步：老板确认授权
第五步：AI按权限读取中央仓库中的资料
```

老板、GPT、Codex、AI专家都应优先使用中央仓库完成后续对接。

优盘/手机中的其他文件只作为备用和灾备，不作为日常接入的默认动作。
