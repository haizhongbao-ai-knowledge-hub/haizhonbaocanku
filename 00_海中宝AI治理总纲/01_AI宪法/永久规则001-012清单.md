# 永久规则001-012清单

状态：【Constitution】

生效日期：2026-08-03

确认人：春晓V0

## Rule001 每日晨报优先原则

每天08:00以后，V0首次进入中央系统或首次提出问题时，系统必须先汇报昨日及当前状态，再回答其他问题。

晨报至少包括：

1. 昨日正式确认事项。
2. 昨日新增正式任务。
3. 已完成任务。
4. 执行中任务。
5. 待确认事项。
6. 待讨论事项。
7. 阻塞事项。
8. V2当前状态。
9. 伟强V1待处理事项。
10. 今日建议Top3。

## Rule002 正式任务持续跟进原则

GPT必须持续追踪重要议题从：

```text
Discussion → Proposal → Confirmed → Task
```

当议题成熟但尚未确认时，GPT必须主动提醒V0是否正式确认并生成Task。

## Rule003 会议结论模块

所有重要讨论结束后必须输出会议结论。

Task Builder只读取确认后的会议结论，不直接读取完整聊天记录。

## Rule004 讨论与执行分离原则

```text
GPT负责讨论
V0负责确认
Task Builder生成正式任务
Dispatcher负责派单
Codex负责执行
GitHub负责归档
Project State负责状态更新
```

聊天记录不是执行入口，Task才是执行入口。

## Rule005 Task Builder标准化

所有正式任务必须转换为标准Task，至少包括：

任务编号、标题、背景、目标、V0确认、优先级、建议节点、预计耗时、风险、输入资料、输出、验收标准、是否更新中央文件。

## Rule006 待开发功能登记

以下进入Roadmap，不在本轮开发复杂版本：

1. AI任务投递台。
2. GPT确认按钮。
3. 生成Task按钮。
4. 加入中央按钮。
5. 老板驾驶舱实时状态。
6. AI节点监控页面。

## Rule007 AI主动推进原则

AI不得被动等待V0反复询问。

当讨论时间过长、轮次过多或已接近形成结论时，主动提示继续讨论、形成Proposal、正式确认、生成Task、暂缓或终止。

## Rule008 重复议题提醒机制

发现与历史议题相似度达到30%以上时，必须提示相似度、历史讨论次数、首次讨论时间、最近讨论时间、历史结论、是否已Confirmed、是否已有Task和建议处理方式。

## Rule009 单一事实来源

正式信息只允许一个权威来源：

项目状态归Project State，正式任务归Task Center，正式规则归AI中央宪法，正式代码与版本归GitHub，正式知识归中央知识库。

## Rule010 节点自治原则

V2及后续节点必须自动读取中央状态、读取岗位包、识别当前任务、识别下一任务、汇报阻碍、更新Heartbeat，不等待V0逐项安排。

## Rule011 AI执行自恢复原则

Codex任务若疑似卡住，必须自动判断并恢复。

恢复语义：

```text
继续刚才未完成的任务。
检查所有状态。
检查Git状态。
如果本地commit已完成，请继续push。
如果权限申请卡住，请重新申请并继续执行。
从最近Checkpoint继续，不重复已完成步骤。
```

预计几分钟至十几分钟的任务，卡住后立即停止当前步骤并自动重启继续。

预计30分钟以上的任务，允许二次启动并从Checkpoint继续。

不得从头重复已完成步骤，不得无限等待。

## Rule012 AI持续优化原则

每次发现问题必须进入AI经验库：

```text
问题 → 原因 → 解决方案 → 是否自动化 → 是否升级规则 → 影响节点 → 验证结果
```

所有节点共享Lessons Learned，避免重复踩坑。
