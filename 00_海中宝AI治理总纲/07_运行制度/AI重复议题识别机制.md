# AI重复议题识别机制

版本：V1.0

状态：【V2.1治理规则】

归属：AI宪法补充规则

## 一、目的

防止不同GPT、Codex、AI专家在不同窗口、不同设备、不同时间反复讨论同一问题，造成信息浪费和执行混乱。

## 二、适用范围

适用于所有：

- GPT窗口
- Codex任务
- AI专家
- AI委员会会议
- 老板驾驶舱汇报
- 新电脑或新账号接入

## 三、扫描范围

AI收到任何重要问题后，必须优先扫描：

| 范围 | 位置 |
| --- | --- |
| 项目状态中心 | `00_老板驾驶舱/01_项目状态中心.md` |
| 中央项目索引 | `00_老板驾驶舱/00_中央项目索引.md` |
| 决策库 | `DECISIONS.md` |
| 当前任务 | `TASKS.md` |
| 同步记录 | `sync_records/三方同步确认记录/` |
| 历史会议 | `projects/AI委员会/meetings/` |
| 知识库 | `knowledge-hub/` |
| 复核报告 | `reviews/` |

## 四、相似度判断

当前阶段采用人工语义判断，不开发复杂算法。

参考标准：

| 相似度 | 判断 | 处理 |
| --- | --- | --- |
| 0%-29% | 新议题 | 可正常讨论 |
| 30%-59% | 相关议题 | 必须提醒历史资料 |
| 60%-79% | 高度相似 | 建议合并或修改历史方案 |
| 80%以上 | 基本重复 | 默认采用历史结论，除非老板要求重开 |

## 五、标准输出格式

发现重复或相似议题时，AI必须先输出：

```text
【重复议题提醒】

历史讨论次数：
相似度：
最近讨论：
历史结论：
涉及文件：

建议：
□ 继续讨论
□ 修改历史方案
□ 合并讨论
□ 直接采用历史结论

是否需要老板确认：
```

## 六、禁止事项

1. 禁止不扫描历史资料就重新回答。
2. 禁止把聊天记忆当作历史结论。
3. 禁止用新方案覆盖已确认文件。
4. 禁止重复创建平行目录或平行制度。

## 七、进入执行条件

重复议题只有在以下条件之一满足后，才能进入执行：

1. 老板明确要求重开讨论。
2. 历史方案已经过期。
3. 出现新的业务事实或数据。
4. 当前问题虽然相似，但执行对象、权限或目标不同。
