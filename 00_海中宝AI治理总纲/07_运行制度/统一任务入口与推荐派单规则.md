# 统一任务入口与推荐派单规则

版本：V1.0

状态：【P0-02/P0-03共用规则】

## 一、唯一正式任务入口

V0确认后的正式任务文件，只投递一次。

运行目录：

```text
D:\海中宝AI协同中心\00_统一任务入口\00_待识别
```

唯一正式根目录：

```text
D:\海中宝AI协同中心\00_统一任务入口
```

禁止继续创建或使用中央仓库内同名的 `00_统一任务入口`。

目录结构：

```text
00_统一任务入口/
├── 00_待识别/
├── 01_待补充/
├── 02_已派单/
├── 03_执行中/
├── 04_待审批/
├── 05_已完成/
└── Archive/
```

## 二、处理流程

```text
V0 GPT确认正式任务
↓
保存到统一任务入口/00_待识别
↓
Dispatcher识别与推荐
↓
V0确认或低风险自动派单
↓
V0 Codex / V2 Codex / 伟强V1 / AI委员会
↓
执行与回传
↓
V0审批
↓
V2正式归档GitHub
↓
状态中心、Heartbeat、老板驾驶舱更新
```

## 三、推荐派单初期规则

当前阶段采用：

```text
推荐派单 + V0确认
```

连续10个真实任务稳定后，才允许低风险任务自动派单。

## 三点五、Dispatcher MVP职责边界

Dispatcher MVP 只允许执行三项：

1. 扫描正式入口的 `00_待识别`。
2. 根据 Task 建议节点移动到 `02_已派单`。
3. 生成唯一派单记录。

禁止：

1. 代替节点执行 Task。
2. 重复创建 Task。
3. 在派单阶段大范围修改中央治理文件。
4. 写入中央仓库内同名 `00_统一任务入口`。

## 三点六、派单状态更新范围

每次派单只更新以下四处：

1. `00_老板驾驶舱/01_项目状态中心.md`
2. `00_老板驾驶舱/07_中央任务中心.md`
3. `HANDOFF.md`
4. `sync_records/dispatcher派单记录/`

幂等要求：

1. 同一 Task 编号不得重复新增多条有效状态。
2. 中央任务中心按 Task 编号原位更新。
3. HANDOFF 同一交接只记录一次。
4. 派单记录一张 Task 只生成一条。
5. 重复运行不得产生重复内容。

## 三点七、普通 Task 派单效率标准

普通 Task 生成与派单：

```text
目标：5分钟内完成
警戒：10分钟
```

超过10分钟优先排查：

1. 是否误用了仓库内同名入口。
2. 是否重复写入状态。
3. 是否重复扫描仓库。
4. 是否等待不必要权限。
5. 是否本地 commit 完成但未 push。

## 四、自动派单启用条件

必须同时满足：

1. V2接口稳定。
2. 连续10个真实任务无重大错误。
3. 任务锁和分支规则稳定。
4. 自动派单准确率达到设定标准。
5. V0正式批准。

启用后：

1. R0/R1低风险任务可自动派单。
2. R2/R3仍需V0确认。

## 六、节点分配

| 节点 | 适用任务 |
| --- | --- |
| V0 Codex | 30分钟以内、不超过3个文件、查询、检查、小修订 |
| V2 Codex | 超过30分钟、5个以上文件、中央治理、自动化、接口、脚本、正式归档 |
| 伟强V1 | 财务口径、经营数据、公司真实业务资料、部门资料补充 |
| AI委员会 | 战略、多方案比较、重大经营风险、多专家分析 |

## 七、禁止事项

1. 禁止多个Codex自由并发修改中央仓库。
2. 禁止V0继续手工判断每个任务发给谁。
3. 禁止V2上线后仍等待人工逐项告诉它做什么。
4. 禁止V3-V6重新设计另一套接入流程。
