# 中央知识治理规范 V1.0

状态：【V2.1治理规则】

## 一、目的

建立海中宝AI中央大脑知识从读取、讨论、执行到复盘的统一治理流程。

## 二、知识治理流程

```text
读取项目状态
↓
读取知识库
↓
判断是否重复
↓
开始讨论
↓
形成方案
↓
Codex执行
↓
老板审批
↓
复盘
↓
更新项目状态
```

## 三、知识分类

| 类型 | 位置 | 说明 |
| --- | --- | --- |
| 状态知识 | `00_老板驾驶舱/` | 当前是什么状态 |
| 宪法规则 | `00_海中宝AI治理总纲/` | 最高原则和运行制度 |
| 企业事实 | `knowledge-hub/enterprise-facts/` | 企业经营基础事实 |
| 部门知识 | `knowledge-hub/department-knowledge/` | HR、财务、运营等岗位知识 |
| 项目文件 | `projects/` | 业务项目和AI委员会 |
| 决策记录 | `DECISIONS.md` | 已确认重大决策 |
| 同步记录 | `sync_records/` | 三方同步依据 |
| 复核报告 | `reviews/` | Codex复核、审计、技术评估 |

## 四、写入规则

正式知识必须满足：

1. 来源清楚。
2. 状态明确。
3. 文件位置明确。
4. 是否需要老板确认明确。
5. 不含真实密码、Token、验证码。
6. 敏感业务数据必须脱敏或按权限存放。

## 五、更新规则

更新知识后，必须判断是否影响：

1. 项目状态中心。
2. 中央项目索引。
3. AI状态中心。
4. 任务清单。
5. 决策记录。
6. AI委员会会议。

## 六、重复治理

发现重复文件时，不直接删除。

处理顺序：

1. 标记重复。
2. 判断主文件。
3. 写入中央文件资产审计报告。
4. 必要时合并内容。
5. 老板确认后再删除或归档。

## 七、AI输出要求

所有AI输出重要方案时必须说明：

1. 依据哪些文件。
2. 是否有历史相似议题。
3. 是否需要老板确认。
4. 是否需要Codex执行。
5. 是否需要更新状态中心。
