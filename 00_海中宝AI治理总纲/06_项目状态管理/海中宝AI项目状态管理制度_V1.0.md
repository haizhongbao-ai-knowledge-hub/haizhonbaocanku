# 海中宝AI项目状态管理制度 V1.0

状态：【确认纳入治理体系，待持续优化】

归档位置：`00_海中宝AI治理总纲/06_项目状态管理/`

## 一、目的

建立海中宝 AI 项目长期运行状态管理机制。

解决：

- 项目持续优化过程中信息分散。
- GPT、Codex、不同设备之间认知不同。
- 老板无法快速掌握整体进展。
- 已确认事项与讨论事项混淆。

## 二、核心原则

### 1. 项目状态透明原则

状态：【宪法级】

海中宝 AI 项目任何阶段，老板均可以快速查询：

- 当前建设情况
- 已完成内容
- 已确认规则
- 待完善事项
- 下一步重点

项目不能依赖聊天记录寻找进度。

### 2. 唯一状态来源原则

所有项目进展最终以：

```text
海中宝AI项目状态总览.md
```

为准。

聊天讨论属于过程。

正式状态文件属于项目事实。

## 三、状态查询机制

不固定单一触发词。

老板可以使用任何类似表达：

- 海中宝AI项目情况
- AI项目进展
- 海中宝AI现在做到哪里
- 最近AI建设怎么样
- 帮我看看还有哪些需要完善
- 现在做到哪一步了
- 帮我看看海中宝AI建设状态

AI 均应理解为进入：

```text
海中宝AI项目状态汇报模式
```

## 四、AI状态汇报标准

所有 GPT、Codex 统一采用《老板驾驶舱简报格式》。

### 海中宝AI项目状态汇报

字段：

- 更新时间
- 当前版本
- 汇报AI

### 第一部分：整体进度

| 模块 | 状态 | 当前情况 |
| --- | --- | --- |
| AI治理体系 |  |  |
| GPT-Codex协同 |  |  |
| 老板驾驶舱 |  |  |
| AI专家体系 |  |  |
| AI应用项目 |  |  |

状态统一：

| 状态 | 定义 |
| --- | --- |
| 已完成 | 文件和规则已经建立 |
| 已确认 | 老板认可方向，可以推进 |
| 优化中 | 已有方案，继续完善 |
| 待确认 | 等老板决策 |
| 讨论中 | 仅作为想法保存 |

### 第二部分：已确定内容

| 内容 | 文件 | 状态 |
| --- | --- | --- |

### 第三部分：正在完善内容

| 项目 | 当前状态 | 下一步 |
| --- | --- | --- |

### 第四部分：老板需要决策事项

只列真正需要老板判断的问题。

格式：

```text
问题：
背景：
建议方案：
需要老板选择：
```

### 第五部分：AI建议下一步优先级

按：

```text
重要性 × 价值 × 紧急程度
```

排序。

## 五、防遗忘机制

任何重要讨论结束，必须形成《AI项目同步记录》。

格式：

```text
日期：
主题：
本次新增确定：
本次新增待完善：
影响文件：
下一步动作：
```

同步记录进入项目仓库。

## 六、多AI统一认知机制

未来多个 GPT、多个 Codex、不同设备必须遵循：

进入项目第一步读取：

- AI治理总纲
- 项目状态总览
- 最新决策记录
- 当前任务

然后输出：

```text
当前理解确认
```

## 七、AI汇报原则

所有 AI 向老板汇报必须：

- 先结论，后过程。
- 先重点，后细节。
- 禁止大量展示没有整理的信息。

## 八、老板驾驶舱关联

老板驾驶舱增加 AI 项目状态模块，包括：

- 当前阶段
- 已完成
- 待完善
- 待老板确认
- 风险提醒
- 下一步建议

## 九、文件维护责任

GPT 负责：

- 整理思考
- 形成结构

Codex 负责：

- 文件维护
- 系统执行

老板负责：

- 最终确认

## 十、长期目标

最终形成一个任何时间、任何地点、任何设备都可以快速恢复上下文的海中宝 AI 企业大脑。
